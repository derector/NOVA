# Аудио- и видеозвонки в NOVA Web

В личном чате доступны аудио- и видеозвонки. Собеседник должен открыть NOVA в браузере, который поддерживает WebRTC, и войти в аккаунт. HTTPS требуется для доступа к микрофону и камере, за исключением localhost в разработке. Браузер запрашивает разрешение при исходящем звонке или принятии входящего.

## Сигналы и маршрутизация

Веб-клиент подписывается на звонки с помощью `call:ready` на авторизованном Socket.IO-соединении. `call:start` принимает ID личного чата и тип звонка. Сервер проверяет членство и отправляет `call:invite` только доступным вкладкам собеседника. После `call:accept` одна конкретная вкладка получает право обмениваться SDP и ICE через `call:signal`. Завершение и отказ передаются через `call:end`. При отключении участника звонок завершается.

Медиа передаётся по WebRTC напрямую либо через TURN. NOVA API передаёт сигнализацию и не записывает медиа. Звонки пока используют один процесс Socket.IO. Для нескольких реплик нужны общий реестр звонков и совместимый адаптер Socket.IO. Сервер проверяет сессию при подключении сокета. Штатный выход из веб-клиента закрывает сокет сразу, а отзыв сессии через REST сам по себе не закрывает ранее подключённый сокет.

## Связь между сетями

Задайте в окружении API `CALL_STUN_URLS` и `CALL_TURN_URLS` со списком URL через запятую. Для coturn включите `use-auth-secret` и установите одинаковое закрытое значение на стороне coturn и API (`CALL_TURN_SECRET`). После проверки участников API выдаёт клиентам временные учётные данные TURN. Максимальная длительность звонка составляет 3 часа, срок учётных данных покрывает её с запасом. Для выхода в интернет рекомендуется проверить TURN по UDP и TLS/TCP и ограничить ретрансляцию в закрытые сети средствами coturn.

Без настроенных STUN/TURN звонок зависит от того, смогут ли браузеры установить прямое соединение. Входящие звонки пока доставляются браузерам с открытым подключением к NOVA. Android-вызовы, фоновые push-уведомления о звонках и групповые звонки потребуют отдельных интеграций.
